# Плагин Taiga для Claude Code

Персональный плагин Claude Code для [Taiga](https://www.taiga.io/): MCP-сервер
из 42 инструментов плюс шесть скиллов, знающих типичные сценарии работы
с трекером — отчёты по спринту, груминг бэклога, триаж issue, перенос спеки
в бэклог, ведение своих задач по ходу кодинга.

Подключение — по адресу инстанса, логину и паролю. Application token
и OAuth не поддерживаются: это осознанный выбор ради простоты настройки
персонального инструмента, а не недосмотр.

## Установка

Сервер уже собран: `server/dist/index.js` закоммичен в репозиторий, и именно
его запускает манифест плагина (`${CLAUDE_PLUGIN_ROOT}/server/dist/index.js`).
Пересобирать его самому нужно только если вы меняете исходники — см. раздел
«Разработка» ниже.

1. Подключить каталог `taiga-plugin/` как плагин Claude Code.
2. Задать переменные окружения для MCP-сервера:

   | Переменная | Обязательна | Значение |
   |---|---|---|
   | `TAIGA_URL` | да | Адрес инстанса без `/api/v1`, например `https://taiga.example.com` |
   | `TAIGA_USERNAME` | да | Логин |
   | `TAIGA_PASSWORD` | да | Пароль |
   | `TAIGA_PROJECT` | нет | Проект по умолчанию (id или slug); любой инструмент может переопределить его параметром `project` |

3. Проверить: попросить Claude выполнить `taiga_whoami`. Успешный ответ
   отдаёт имя пользователя и список доступных проектов с их slug'ами.

Если что-то не подключилось, инструменты Taiga вернут читаемую ошибку
(неверный `TAIGA_URL`, отказ логина, отсутствующая переменная) — подробный
разбор типичных сообщений есть в скилле `taiga-setup`.

## Что внутри

**42 инструмента**, схема — **31 428 символов** (~7 857 токенов) при
жёстком пределе 32 000 символов (~8 000 токенов); за этим следит
`test/budget.test.ts`.

CRUD-фабрика на пять действий (`list`, `get`, `create`, `update`, `delete`)
для каждого из шести ресурсов даёт 30 инструментов:

`userstory`, `task`, `issue`, `epic`, `sprint`, `wiki`.

Плюс 12 сквозных:

- `taiga_project_list`, `taiga_project_get`, `taiga_project_schema`
- `taiga_comment_list`, `taiga_comment_add`
- `taiga_search` — полнотекстовый поиск по историям, задачам, issue, эпикам и wiki
- `taiga_bulk_create` — пачка историй, задач или issue за один вызов
- `taiga_stats` — статистика проекта или спринта с бёрндауном
- `taiga_attachment_list`, `taiga_attachment_upload`, `taiga_attachment_download`
- `taiga_whoami`

Шесть скиллов в `skills/`: `taiga-setup`, `taiga-sprint-report`,
`taiga-backlog-grooming`, `taiga-stories-from-spec`, `taiga-issue-triage`,
`taiga-worklog`. Каждый описывает, когда применяться, какими инструментами
пользоваться и что требует явного согласия пользователя.

## Особенности

- **Имена вместо ID.** Статусы, приоритеты, severity, типы issue и
  исполнители указываются человеческими именами («In progress», «High»,
  «Иван Петров»); перевод в числовые ID Taiga (свои в каждом проекте) делает
  сервер. Если имя не резолвится, ошибка перечисляет допустимые значения.
- **Экономный вывод.** По умолчанию (`fields: "slim"`) возвращается срез
  из 8–10 полей вместо полного объекта Taiga (у user story это 53 поля).
  На девяти историях песочницы это ~87% сокращения объёма JSON. Есть и
  `fields: "full"`, и явный список нужных полей.
- **Эпики.** `taiga_userstory_create` и `taiga_userstory_update` принимают
  поле `epic` — тему (subject) эпика, к которому привязывается история;
  пустая строка в `epic` при обновлении отвязывает историю от всех эпиков.
  `taiga_bulk_create` тоже понимает `epic`, но только для user stories —
  для task и issue это поле возвращает ошибку по конкретному элементу,
  а не тихо игнорируется.
- **Бэклог — это фильтр, не отдельный ресурс.** `taiga_userstory_list` без
  фильтров отдаёт вообще все истории проекта, включая уже взятые в спринт.
  Чтобы увидеть именно бэклог (истории, не привязанные ни к одному спринту),
  нужен параметр `in_backlog: true` — другого способа получить этот список
  нет.
- **Удаление под защитой.** Все `_delete` требуют `confirm: true`. Это защита
  от случайного вызова, а не замена согласию пользователя — скиллы
  предписывают спрашивать явно до вызова.
- **Токен обновляется сам.** Access-токен Taiga живёт сутки; на HTTP 401
  сервер один раз тихо перелогинивается и повторяет запрос.
- **Массовое создание ограничено.** `taiga_bulk_create` — не более 50
  элементов за вызов, каждый создаётся независимо: неудача одного не
  останавливает остальные, результат приходит по каждому элементу отдельно.

## Безопасность

`taiga_attachment_upload` принимает абсолютный путь к файлу на диске и
читает этот файл, чтобы приложить его к истории, задаче, issue или эпику.
Инструмент прочитает **любой** файл, на который его направят, — в этом и
состоит его назначение: приложить к задаче можно скриншот, лог или документ
из любого места на диске. Это означает, что модель, управляющая этим
инструментом, может прочитать содержимое произвольного локального файла,
путь к которому она укажет. Учитывайте это при решении, устанавливать ли
плагин и в каком окружении запускать Claude Code.

## Чего плагин сознательно не делает

- **Webhooks, export/import, custom attributes, timeline** — не входят
  в заявленные сценарии персонального инструмента.
- **Комментарии** (`taiga_comment_list` / `taiga_comment_add`) работают на
  user stories, tasks, issues и epics, но **не на wiki-страницах** — для wiki
  таких инструментов нет.
- **Wiki-страницы редактируются полной заменой содержимого.** `taiga_wiki_update`
  принимает новый Markdown целиком; добавления к существующему тексту
  (append), в отличие от `_update` у остальных ресурсов, нет.
- **Вложения ограничены 100 МБ** — это не собственное решение плагина,
  а предел, на котором сам gateway Taiga отбрасывает запрос.
- **Application tokens, OAuth, мультиаккаунтность.** Один логин, одна
  неявная сессия на процесс.

## Разработка

Тесты идут против локального стенда Taiga — как его поднять и заполнить
тестовыми данными, написано в `../infra/README.md`.

```bash
cd server
npm install            # только для разработки; конечному пользователю плагина не нужен
npm test                # всё, включая интеграционные тесты против стенда
npm run typecheck
npm run build            # пересобрать dist/index.js
```

`test/budget.test.ts` следит, чтобы схема инструментов не превышала
32 000 символов (~8 000 токенов), и что имя каждого инструмента соответствует
`taiga_[a-z_]+`. Падение этого теста — сигнал, что витрина разрослась и новую
функциональность надо оформлять скиллом, а не ещё одним инструментом.

`dist/index.js` собирается esbuild'ом в один файл со всеми зависимостями
и коммитится в репозиторий — именно поэтому плагину не нужен `npm install`
на машине, где его использует Claude Code.
