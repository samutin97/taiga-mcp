# Приоритизация бэклога

Методы, формулы и когда какой — в `reference.md`. Здесь — порядок действий.

## Порядок

1. Размер: `taiga_userstory_list` с `in_backlog: true`. Больше 30 историй —
   сначала MoSCoW (шаг 2), иначе сразу шаг 3.
2. MoSCoW: предложи разбивку must / should / could / won't, дождись согласия,
   проставь тегами `must`, `should`, `could`, `wont` через `taiga_userstory_update`
   с `add_tags`. Дальше работаем только с must и should.
3. Собери оценки в разговоре: для каждой истории — влияние и усилия (матрица),
   а если нужен точный порядок — reach, impact, confidence, effort (RICE).
   Для эпиков — user value, time criticality, risk reduction, duration (WSJF).
   Не выдумывай цифры за пользователя: спрашивай или предлагай с пометкой «предполагаю».
4. Запиши оценки в JSON-файл в scratchpad
   (`{"method":"rice","items":[{"ref":42,"subject":"…","reach":…,"impact":…,"confidence":…,"effort":…}]}`)
   и посчитай: `node "${CLAUDE_PLUGIN_ROOT}/scripts/score.mjs" <файл>`.
5. Покажи таблицу пользователю и дождись согласия.
6. Запиши **только порядок**: `taiga_userstory_update` с `backlog_order` по
   возрастанию (1, 2, 3…) по одной истории за вызов. Числа RICE/WSJF в Taiga не
   пишутся — они устаревают и выглядят машинно.

## Чек-лист перед записью

- [ ] пользователь видел таблицу и согласился
- [ ] в бэклог не записано ничего, кроме `backlog_order` и, если просили, MoSCoW-тегов
- [ ] истории в работе (`status` не начальный) не трогал без отдельной просьбы
