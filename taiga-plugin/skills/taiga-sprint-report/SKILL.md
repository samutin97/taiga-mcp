# Отчёты по Taiga

Этот скилл только читает. Ничего не меняй без отдельной просьбы.

## Статус спринта

1. `taiga_stats` с параметром `sprint` — очки, сделанное, бёрндаун по дням.
2. `taiga_userstory_list` с фильтром `sprint` — состав спринта.
3. Сопоставь: расхождение `open_points` с `optimal_points` в конце ряда
   `burndown` показывает отставание.

Без параметра `sprint` тот же `taiga_stats` даёт цифры по всему проекту
и скорость команды (velocity) — не спринтовый отчёт, а более общий.

## Обязательства против скорости

`taiga_stats` со `sprint` даёт `total_points` — сколько поинтов команда взяла
в спринт. `taiga_stats` без `sprint` даёт `speed` — среднюю скорость по
прошлым спринтам того же проекта. Если `total_points` превышает `speed`
больше чем на 20 % — скажи это прямо: команда либо не уложится, либо уже
режет скоуп, и это стоит проговорить, а не сгладить.

## Банкротство бэклога

«Открытых в спринте больше, чем закрытых» — обычное состояние почти любого
спринта до последних дней, это не сигнал. Считай честно: приток против
выпуска за окно длиной со спринт (по умолчанию 14 дней). Собери
`taiga_userstory_list` по всему проекту, без фильтра `sprint`
(`limit: 200`, при `has_more: true` — следующая `page`), с
`fields: ["ref", "created_date", "finish_date", "is_closed"]`. Посчитай:
приток — истории, у которых `created_date` попадает в последние N дней;
выпуск — истории с `is_closed: true`, у которых `finish_date` тоже в этом
окне. Приток больше выпуска — скажи прямо, с обоими числами. Тот же расчёт
(`backlog-bankruptcy`) делает `scripts/audit.mjs` для всего бэклога; если
нужен полный аудит, а не только эта цифра, — это `taiga-backlog-health`.

## Блокировки

`is_blocked` есть в `slim` у историй, но не у задач; `blocked_note` нет в
`slim` ни там, ни там — запрашивай явным списком полей, он не ограничен
`slim`/`full`: `taiga_userstory_list fields=["ref","subject","status","is_blocked","blocked_note"]`,
так же для `taiga_task_list`. Собери всё с `is_blocked: true` — списком,
рядом с `blocked_note`. Пустой `blocked_note` — отдельный сигнал: блокировка
стоит, а что мешает, никто не написал.

## Сводка для стендапа

- Сделано: `taiga_userstory_list` с `is_closed: true` и нужным спринтом.
- В работе: `status: "In progress"`.
- Заблокировано: подробности — раздел «Блокировки» выше.

## Что не двигается

`taiga_userstory_list` возвращает `total_comments`. История с нулём комментариев,
висящая в работе много дней, — кандидат в «застряло». Уточни детали через
`taiga_comment_list` только по тем историям, о которых собираешься говорить, —
не гоняй его по всему списку.

## Делегирование

Для полного отчёта (спринт целиком, состояние проекта) запускай субагента
`taiga-reporter`, а не собирай выгрузку в основном контексте сам: наружу
должны попасть только выводы — цифры и заключения, а не списки историй и
сырые ответы инструментов. Короткий точечный вопрос («что там с #17») можно
закрыть и без субагента.

## Экономия контекста

Не запрашивай `fields: "full"` для списков: `slim` даёт около десяти нужных
полей, а `full` — свыше пятидесяти на каждый элемент. На девяти историях это
разница порядка 400 токенов против 4800; на спринте побольше цена растёт
пропорционально. Полный срез оправдан только для одного конкретного элемента,
когда нужно поле, которого нет в `slim`.

## Подача

Показывай цифры и выводы, а не выгрузку. Пользователю нужно понять,
успевает ли команда, а не прочитать список из сорока заголовков.
