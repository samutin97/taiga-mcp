# Отчёты по Taiga

Этот скилл только читает. Ничего не меняй без отдельной просьбы.

## Статус спринта

1. `taiga_stats` с параметром `sprint` — очки, сделанное, бёрндаун по дням.
2. `taiga_userstory_list` с фильтром `sprint` — состав спринта.
3. Сопоставь: расхождение `open_points` с `optimal_points` в конце ряда
   `burndown` показывает отставание.

Без параметра `sprint` тот же `taiga_stats` даёт цифры по всему проекту
и скорость команды (velocity) — не спринтовый отчёт, а более общий.

## Сводка для стендапа

- Сделано: `taiga_userstory_list` с `is_closed: true` и нужным спринтом.
- В работе: `status: "In progress"`.
- Заблокировано: возьми из выдачи истории с `is_blocked: true` — это поле
  уже есть в срезе `slim` по умолчанию, отдельный вызов не нужен.

## Что не двигается

`taiga_userstory_list` возвращает `total_comments`. История с нулём комментариев,
висящая в работе много дней, — кандидат в «застряло». Уточни детали через
`taiga_comment_list` только по тем историям, о которых собираешься говорить, —
не гоняй его по всему списку.

## Экономия контекста

Не запрашивай `fields: "full"` для списков: `slim` даёт около десяти нужных
полей, а `full` — свыше пятидесяти на каждый элемент. На девяти историях это
разница порядка 400 токенов против 4800; на спринте побольше цена растёт
пропорционально. Полный срез оправдан только для одного конкретного элемента,
когда нужно поле, которого нет в `slim`.

## Подача

Показывай цифры и выводы, а не выгрузку. Пользователю нужно понять,
успевает ли команда, а не прочитать список из сорока заголовков.
