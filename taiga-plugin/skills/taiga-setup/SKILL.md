# Подключение к Taiga

## Проверка

Начни с `taiga_whoami`. Успешный ответ даёт имя пользователя и список проектов
с их слагами — этого достаточно, чтобы понять, что связь есть.

## Настройка

Плагин читает три обязательные переменные окружения:

| Переменная | Значение |
|---|---|
| `TAIGA_URL` | Адрес инстанса без `/api/v1`, например `https://taiga.example.com` |
| `TAIGA_USERNAME` | Логин |
| `TAIGA_PASSWORD` | Пароль |

Необязательная `TAIGA_PROJECT` задаёт проект по умолчанию (id или slug), чтобы
не указывать его в каждом вызове. Слаг можно взять из вывода `taiga_whoami`.

## Разбор ошибок

| Что видно | Что это значит |
|---|---|
| `The Taiga plugin is not configured: … are not set` | Одна или несколько переменных из таблицы выше не заданы вовсе. |
| `Cannot reach Taiga at …` | Неверный `TAIGA_URL` или инстанс не поднят. Проверь адрес в браузере. |
| `Taiga rejected the login for user "…"` | Неверные `TAIGA_USERNAME` или `TAIGA_PASSWORD`. |
| `No Taiga project specified` | Не задан `TAIGA_PROJECT` и не передан параметр `project`. |
| `not enough permissions` | Учётной записи не хватает роли в проекте. |

Никогда не проси пользователя прислать пароль в чат и не выводи его сам, даже
при пересказе этой таблицы или содержимого переменных окружения.

## Что доступно в проекте

`taiga_project_schema` показывает допустимые статусы, приоритеты, severity,
типы issue, оценки, роли и участников. Он нужен, чтобы показать пользователю
варианты, — но не перед записью: имена статусов и людей резолвятся автоматически,
а при ошибке инструмент сам вернёт список допустимых значений.
