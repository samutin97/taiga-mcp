# Как решаю, в какой форме записать требование

Голос и форма — разные слои. `taiga-voice` отвечает за то, как звучит текст:
первое лицо, живая речь, без канцелярита. Этот скилл отвечает за форму: какую
рубрику завести, сколько правил написать, когда под правило нужен пример и в
каком виде. Рубрика `##` — часть формата, не протокол; протокол — рубрика с
двоеточием внутри строки, вроде «Контекст: ...» — с ней по-прежнему нельзя.

## Рубрики по сущностям

| Сущность | Рубрики |
|---|---|
| Эпик | `## Цель`, `## Границы`, `## Готово, когда` |
| История | `## Описание`, `## Критерии приёмки`; по месту — `## Открытые вопросы`, `## Примеры`, `## Таблица решений`, `## Переходы состояний` |
| Задача | `## Что сделать`, `## Как проверить`; у бековой ещё `## Контракт` |
| Задача-спайк | `## Вопрос`, `## Таймбокс`, `## Что считаем ответом` |
| Issue — Bug | `## Предусловия`, `## Шаги`, `## Ожидаемый результат`, `## Фактический результат`, `## Окружение` |
| Issue — Question | `## Вопрос`, `## Контекст`, `## Варианты`, `## Таймбокс` |
| Issue — Enhancement | `## Описание`, `## Критерии приёмки` |
| Wiki — ADR | `## Статус`, `## Контекст`, `## Решение`, `## Последствия` |

Иерархию строю заголовками и таблицами, а не вложенными списками: Taiga
схлопывает отступы вложенного списка при отображении, и уровень пропадает —
поэтому под-пункты и, где нужна связка условие→результат, идут таблицей, а
не списком со вложенным списком внутри.

## Критерии: правило и пример — слои, не альтернатива

Правила пишу всегда, 3–5 строк, каждое отдельной строкой, без буллетов — как
в `## Критерии приёмки`. Шестое правило не появляется никогда: как только их
стало больше пяти, это сигнал разрезать историю на две, а не квота, которую
можно исчерпать. Под правилом, которое не очевидно само по себе, добавляю
конкретный пример — правило без примера двусмысленно, пример без правила
ничего не объясняет сам по себе.

## Какую форму выбрать

Решётка общая для эпика, истории, задачи, issue. Беру первое совпадение
сверху вниз — совпало раньше, дальше не смотрю. Первые две строки уводят
требование в другую сущность целиком, остальные — форма критерия внутри
истории.

| Признак | Форма |
|---|---|
| Это дефект, а не требование | Шаблон бага — `reference.md` |
| Это вопрос или исследование, а не готовое требование | Issue-question либо задача-спайк с таймбоксом |
| Качество, и есть условие срабатывания — явное или подразумеваемое (нагрузка, объём, состояние системы) | EARS + измеримость: шкала, способ измерения, цель, минимум |
| Качество, и условия срабатывания нет — речь о свойстве системы вообще | Только измеримость, EARS не натягиваю |
| Поведение зависит от текущего состояния сущности | Матрица переходов: состояние × событие → новое состояние, и отдельно — что запрещено |
| Результат зависит от сочетания условий, и словами это уже читается тяжело | Таблица решений: условия × результат |
| Ветвление, реакция на отдельные события | EARS-предложения |
| Нужны точные данные, или сценарий станет автотестом | Пример в Gherkin, в блоке кода |
| Ничего из этого не подошло | Список правил |

Триггер с условием и без — легко перепутать: якорь такой же, как выше про
эпик/историю — есть у требования условие срабатывания (нагрузка, объём,
состояние системы), явное числом или подразумеваемое словами вроде «под
нагрузкой», — пишу EARS-предложение поверх измеримости; условия нет, речь
о свойстве системы в целом («не должна тормозить», «должна быть удобной») —
только измеримость, без EARS-обёртки. Пример обеих форм рядом — в
`reference.md`.

Полные шаблоны — все пять видов EARS, Gherkin со сценарием и таблицей
примеров, таблица решений, матрица переходов, шаблон бага и ADR, с
примерами и пометкой «когда применяю / когда не применяю» — в `reference.md`.

## Мост к тестам

Из таблицы решений — по тест-кейсу на строку, из матрицы переходов — по
кейсу на переход. Кейсы заводит скилл тест-плана, не этот.

## Три уровня проверки

- Блокирую запись: у бага нет шагов или одного из результатов; у истории нет
  ни одного проверяемого критерия; у бековой задачи нет контракта и нет
  ссылки на него.
- Предупреждаю, но пишу: правил больше пяти; неочевидное правило без
  примера; требование качества без измеримости; у крупной истории нет ни
  одного открытого вопроса.
- Не трогаю никогда: текст, который написал человек сам, и старые тикеты —
  только показываю, что заметил, а не переписываю чужое.

## Чего не выдумываю

Критерий, которого нет в источнике — спеке, переписке, разговоре с
человеком, — не появляется в тексте. Вместо него — строка в
`## Открытые вопросы`. Пустой список вопросов лучше придуманного критерия:
для меня это главное ограждение от выдумки.
