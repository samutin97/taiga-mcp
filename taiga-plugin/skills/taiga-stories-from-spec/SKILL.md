# Из текста в бэклог Taiga

## Порядок

1. **Разбери текст.** Выдели самостоятельные единицы работы. Одна история —
   один проверяемый результат, а не один абзац исходника.
2. **Покажи план.** Выведи предлагаемый список заголовков с краткими описаниями
   и дождись согласия. Это обязательный шаг: создание двадцати историй по
   неверно понятому документу дороже, чем один уточняющий вопрос.
3. **Создай.** `taiga_bulk_create` с `resource: "userstory"`, до пятидесяти
   элементов за вызов.
4. **Разбери результат.** Инструмент возвращает `created` и `failed`.
   Разбери причины неудач и повтори запрос только с ними — не создавай всё заново.

## Формат элементов

Каждый элемент принимает те же поля, что `taiga_userstory_create`:

```json
{
  "subject": "Пользователь может сбросить пароль по email",
  "description": "Критерии приёмки:\n- письмо приходит в течение минуты\n- ссылка живёт 24 часа",
  "status": "New",
  "tags": ["auth"]
}
```

Статусы, исполнителей, оценки (`points: "5"`) и спринт (`sprint: "<название>"`)
указывай человеческими именами — резолв в числовые ID происходит сам, ровно как
в `taiga_userstory_create`. Поля `points` и `sprint` есть только у user stories;
в элементе `resource: "task"`/`"issue"` такой элемент вернётся в `failed`
с понятной причиной, а не будет создан молча без них.

## Задачи под историями

Задачи создавай вторым проходом, после того как истории получили номера:
`taiga_bulk_create` с `resource: "task"`, где `user_story` — номер `#ref`
созданной истории из ответа первого вызова.

## Эпики

Если материал явно делится на крупные направления, можно предложить завести
эпики через `taiga_epic_create` — но не по своей инициативе, спроси.
Привязывай истории к эпику полем `epic` — оно работает и в
`taiga_bulk_create`: добавь `"epic": "<название эпика>"` в элемент, и
история будет создана уже привязанной к нему, без отдельного прохода
`taiga_userstory_update` после пакетной заливки. Поле `epic` в элементах
`resource: "task"`/`"issue"` не имеет смысла — такой элемент вернётся
в `failed` с понятной причиной.

## Чего не делать

Не выдумывай критерии приёмки, которых нет в источнике. Если раздел документа
слишком расплывчат, чтобы стать историей, скажи об этом, а не сочиняй.
