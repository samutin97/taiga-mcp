# Оценка в поинтах

Шкала, калибровка команды и оба порога — в `reference.md`. Кто на проекте
какой роли и как из оценок задач считаются поинты истории — в `taiga-model`;
этот расчёт здесь не переписываю, только использую. Разбивка истории на
задачи — работа `taiga-stories-from-spec`, не этого скилла: если задач нет и
нужна не прикидка, а полная декомпозиция, отправляю туда.

## Порядок

1. Допустимые значения шкалы беру из проекта — `taiga_project_schema`,
   `lookups.points` — не считаю ряд 0–40 заранее данным.
2. У истории уже есть задачи (`taiga_task_list` с `user_story`) — оцениваю
   их, а не историю целиком: у каждой задачи — роль и оценка. Как задаётся
   роль и как из оценок задач считаются поинты истории по каждой роли — в
   `taiga-model`; поинты истории руками не трогаю.
3. У истории задач нет — это раннее планирование, точной оценки быть не
   может. Даю прикидку через `taiga_userstory_update` с `points`: строка
   (`"5"`) — одно число в основную роль проекта, объект (`{"Front": "5",
   "Back": "3"}`) — своё число по каждой роли, когда фронт и бек явно
   разного объёма. Обе формы прямо называю прикидкой: как только у истории
   появятся оценённые задачи, сервер пересчитает поинты по каждой роли и
   заменит эти числа своими.
4. Оценивая задачу или прикидку по истории, называю ориентир: место в
   калибровке (`reference.md`) и, если найдётся, одну-две похожие уже
   закрытые задачи той же роли («сложнее задачи #45 на 2, ближе к #52»,
   `taiga_task_get` с `fields: "full"` — иначе «Оценку» не увидеть). Не
   выдумываю точность, которой в сравнении нет.
5. Сверяюсь с прошлым через `taiga_stats`: без `sprint` — скорость проекта
   (`speed`) и закрытые поинты, с `sprint` — что уже сделано и загрузка
   людей (`load`, `of_capacity`). Свою «скорость» руками не считаю.
6. Два порога, не один: задача больше 10 — кандидат на дробление, предлагаю
   раздробить её на более мелкие шаги той же роли раньше, чем записываю ей
   число. Сумма по роли у истории больше 40 — история не влезает в спринт
   одного человека этой роли; предлагаю разрезать историю вертикально по
   пользе (SPIDR — в `reference.md`). Резать или нет — решает человек, сам
   не режу.
7. Показываю таблицу «задача (или история) — ориентиры — предложение»,
   жду согласия.
8. Записываю по одному объекту за вызов: задачам — `taiga_task_update` с
   `estimate` (и `role`, если тег ещё не стоит); историям без задач —
   `taiga_userstory_update` с `points`. Ответ уже несёт новое значение
   (`story_points` у задачи, `points` у истории) — показываю его, а не
   обещаю.

## Чек-лист

- [ ] если у истории есть задачи — оценка на задачах, поинты истории руками
      не вписаны
- [ ] если задач нет — записанное на историю число прямо названо прикидкой
- [ ] ни одной задачи больше 10 без предложения раздробить
- [ ] ни одной суммы по роли больше 40 без предложения разрезать историю —
      и без отдельного решения человека
- [ ] пользователь согласился с таблицей до записи
