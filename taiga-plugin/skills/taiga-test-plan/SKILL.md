# Тест-план к истории

В Taiga нет сущности «тест-кейс». Кейс — это задача под историей; дефект —
issue со ссылкой на историю и кейс. Что проверять и как — в `reference.md`.

## Порядок

1. Прочитай историю: `taiga_userstory_get` с `fields: "full"` (нужно описание).
2. Выпиши проверки из описания и критериев. Ничего не додумывай: если критерий
   нельзя проверить — скажи об этом, а не сочиняй шаг.
3. Каждый кейс — задача: `subject` начинается с «Проверить: …», в `description`
   шаги обычным текстом, ожидаемый результат последней фразой. Без рубрик
   «Шаги:», «Ожидаемый результат:».
4. Покажи список кейсов, дождись согласия, создай через `taiga_bulk_create`
   с `resource: "task"` и `user_story: <#ref истории>`.
5. Готовность к тесту — чек-лист Definition of Done из `reference.md`;
   если что-то не выполнено, история не переводится в «готова к тесту».
6. Найденный дефект — `taiga_issue_create` с `type: "Bug"`, в описании
   «История #42, кейс #57» и что именно расходится с ожиданием.

## Чек-лист

- [ ] у каждого кейса один ожидаемый результат
- [ ] кейсы покрывают каждый критерий из истории хотя бы раз
- [ ] негативные сценарии есть, если история про ввод данных или права
