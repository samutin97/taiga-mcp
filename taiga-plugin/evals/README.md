# Evals: taiga-plugin

Как запускать полный набор (кроме `holdout/`, см. ниже):

```bash
cd taiga-plugin
claude plugin eval . --ablation with-without --runs 3 --max-cost-usd 15 --threshold 0.8 --no-publish --trust-plugin
```

Только активацию скиллов (без голоса):

```bash
claude plugin eval . --case "taiga-*" --ablation with-without --runs 3 --max-cost-usd 15 --no-publish --trust-plugin
```

Только голос:

```bash
claude plugin eval . --case "voice/*" --ablation none --runs 3 --max-cost-usd 10 --no-publish --trust-plugin
```

## Структура

- `<skill>/positive-1/` и `<skill>/negative-1/` — по одному кейсу активации на
  каждый из 10 вызываемых скиллов (`taiga-voice` не вызывается напрямую и своих
  кейсов активации не имеет). Промпт — как запрос набрал бы пользователь, без
  имени скилла. Единственный грейдер — `graders/skill.md`, `type: tool_used`,
  `tool: Skill`, `input_match: <имя скилла>`. Он же — «индикатор срабатывания
  плагина» в терминологии `--ablation`, но здесь ему дополнительно выставлен
  `arm: both` (а не оставлен «display-only» умолчание для `tool: Skill`),
  потому что именно от него зависит смысл дельты: без плагина `Skill` с этим
  именем вызвать нельзя (`min` по умолчанию 1) — кейс красный; с плагином он
  обязан сработать — кейс зелёный. Без `arm: both` грейдер помечается
  `with-only` и не входит в счёт, а без другого outcome-грейдера итоговый
  `score` кейса остаётся нулевым в обеих руках — сравнивать было бы нечего.
  У `negative-1/` тот же грейдер, но `min: 0, max: 0` — скилл не должен
  сработать ни с плагином, ни без него.
- `voice/1..6/` — шесть кейсов голоса: история, задача, issue, комментарий,
  bulk из трёх историй, `append_description`. Промпт даёт исходник (заметки
  со встречи, чата поддержки и т.п.) и просит завести это в Taiga. Два
  грейдера: `graders/regex.md` (`type: regex`, `target: mock_calls`,
  `match: not_contains`) — одна комбинированная регулярка из `hard` (сейчас
  только `ai-authorship`) плюс `heading-label`, `as-a-user`, `emoji` из
  `scripts/voice-rules.json`; и `graders/voice-judge.md` (`type: llm`,
  `focus: mock_calls`) — бинарный судья с критикой и вердиктом PASS/FAIL,
  текст и четыре few-shot примера — в самом файле.
- `holdout/` — по одному дополнительному кейсу для `taiga-stories-from-spec`,
  `taiga-prioritize` и голоса. **Не входит в обычный прогон** (не матчится
  `taiga-*` или `voice/*` глобами выше) и не используется при доводке
  описаний скиллов — только чтобы разово подтвердить на приёмке, что скилл
  не переобучен под конкретные формулировки из `positive-1`/`voice/N`.
  Запускать явно, отдельным вызовом с `--case holdout/*`, и не чаще одного
  раза на ревью.
- `mocks/plugin_taiga_taiga/` — канонические ответы MCP-сервера плагина для
  `--mocks record` (по умолчанию, без `--allow-real-servers`): `_tools.json`
  (срез `tools/list` для замоканных инструментов — без него агент видит их
  с «permissive schema» без описания) и по одному `<tool>.md`
  (`type: fixed`, тело — сырой JSON) на `taiga_whoami`, `taiga_project_schema`,
  `taiga_userstory_list` (9 историй стенда, slim), `taiga_stats` (проект
  целиком), `taiga_userstory_create`, `taiga_task_create`, `taiga_issue_create`,
  `taiga_comment_add`, `taiga_bulk_create`, `taiga_userstory_update` — у
  созданных/обновлённых записей заведомо фиктивные `ref` (9001+), не
  пересекающиеся с реальными данными стенда.

## Что значат дельты

`--ablation with-without` запускает каждый кейс дважды: «с плагином» и «без».
Для кейсов активации (`positive-1`/`negative-1`) дельта — это буквально
разница между «скилл вызвался» и «скилла и его триггеров вообще не существует
для модели». Единица — ожидаемый результат для позитивных кейсов, ноль — для
негативных (в обеих руках, поскольку `min: 0, max: 0` выполняется тривиально
и без плагина). Провал позитивного кейса **без** плагина — не находка, это
и есть работающий контроль (без скилла результата взяться неоткуда). Провал
**с** плагином — повод править триггеры в `description` скилла или его тело,
а не сам кейс: скилл либо не подхватывает фразу пользователя, либо жанр
промпта пересекается с другим скиллом сильнее, чем с целевым.

Для кейсов `voice/*` дельта менее содержательна (без плагина замоканных
MCP-инструментов не существует, писать нечему — грейдерам буквально нечего
проверять), поэтому обычный прогон голоса — `--ablation none`.

## Доводка скиллов

При правке `description`/тела скилла из-за провала `positive-1`/`negative-1`
или `voice/N` — не трогайте формулировки `holdout/`. Если после исправления
`holdout/*` тоже проходит — хорошо, но это не критерий приёмки самого
исправления (тот — обычный набор); если `holdout/*` начинает шататься при
стабильном обычном наборе, это сигнал, что описание скилла подогнано под
конкретные фразы, а не под класс запросов.
